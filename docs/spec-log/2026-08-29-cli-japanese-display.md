# SPEC壁打ちログ: CLI表示を日本語化する（NFR-5の見直し）

- 起票日: 2026-08-29
- 関連SPEC項目: NFR-5（ASCII限定 → 日本語表示へ改訂）、12章
- ステータス: 決定済み
- 参加: ユーザー / Claude

## 背景・きっかけ

ユーザーから、画面下部の操作ヘルプが英語（`Arrows:Move  Up/X:RotateR ...`）で表示されている
スクリーンショットとともに「日本語にしてほしい。要件としても CLI 上に表示されるものは日本語にする」
という依頼。

現状の NFR-5 は「`ui_curses.py` が `addstr` で描画する文字列は ASCII のみ」と定めている。これは
2026-08-29 のバグ修正で追加されたもので、windows-curses（PDCurses ベース）が全角文字を含む文字列を
`addstr` で描画する際に**表示幅を1文字=1セルとして数え、全角グリフの右半分に次の文字が重なって描画される**
（斜めにずれて重なる）不具合が実機で確認されたため。単純に日本語へ戻すとこの不具合が再発する。

## 論点

- 全角文字の重なり不具合をどう回避して日本語を出すか。
- 日本語化する対象文字列の範囲。
- 盤面の整列（罫線・セル）への影響。
- NFR-5 をどう書き換えるか（完全撤廃ではなく条件付き許可にする）。
- 端末フォント依存のリスクをどこまで許容するか。

## 検討した選択肢

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| A. 明示的な桁計算で描画 | `unicodedata.east_asian_width` で各文字の表示幅(1/2)を求め、`draw_text(y, x, ...)` ヘルパが1文字ずつ（またはラン単位で）明示 x 位置に `addstr` して x を幅ぶん進める。`locale.setlocale(LC_ALL, "")` も併用 | PDCurses のカーソル前進バグに依存しない。確実。盤面と分離した右サイドバーに影響が閉じる | ui_curses.py に描画ヘルパ追加が必要。曖昧幅(A)文字と端末フォント次第で1桁ずれる可能性は残る |
| B. locale 設定のみ＋1行1 addstr | `locale.setlocale` を入れ、各行を単一 addstr で描画（現状ほぼこの構造） | 変更が小さい | 実機の不具合原因はラン内の幅誤カウントであり、これだけでは再発の可能性が高い |
| C. 日本語は装飾的な箇所のみ | タイトルや PAUSED 等の単独行だけ日本語、ヘルプやラベルは英語のまま | リスク最小 | ユーザー要望（CLI表示は日本語に）を満たさない |
| D. curses をやめて自前 ANSI 描画 | print/ANSI エスケープで全描画を自作 | 幅を完全に自前管理 | 影響範囲が大きすぎる。今回の要望に対し過剰 |

## やり取りの要旨

- Claude: NFR-5 は実機バグ由来。日本語へ戻すだけでは重なり再発。安全に出すには A（明示的な桁計算）が必要と提示。
- Claude の問い1「実装方針は案 A（幅計算ヘルパ追加）でよいか」→: ユーザー「案 A（幅計算ヘルパを追加して日本語化）で進める」。
- Claude の問い2「端末フォントが CJK 等幅でない場合の桁ずれに備え、環境変数で ASCII 表示へ切り替えられるようにするか」→: ユーザー「日本語固定・切替なし」。

## 決定事項

- 案 A を採用。`ui_curses.py` に幅認識の描画ヘルパ `_draw_text()`（`_char_width()` で
  `east_asian_width` を判定し全角=2桁・半角=1桁、確定桁へ1文字ずつ `addstr`）を追加する。
- `main()` で `locale.setlocale(locale.LC_ALL, "")` を実行する。
- 日本語化する表示: タイトル（テトリス）、サイドバーのラベル（スコア/レベル/ライン/ネクスト）、
  `-- 一時停止中 --`、`ゲームオーバー`、`Q キーで終了`、操作ヘルプ
  （`矢印キー:移動  上/X:右回転  Z:左回転  スペース:ハードドロップ  P:一時停止  Q:終了`）。
- ASCII のまま維持: 盤面の罫線（`|` `+` `-`）、セル表現（`[]`）、スコア等の数値、ネクストのミノ種別記号。
- 操作ヘルプでは曖昧幅（`east_asian_width='A'`）になる矢印記号 `←→↑` を使わず、
  「矢印キー」「上」という語に置き換える。
- ASCII へ切り替えるオプションは設けない（日本語固定）。端末フォントが CJK 等幅でない場合の
  桁ずれは既知の残存リスクとして許容する。
- NFR-5 を「ASCII 限定」から上記方針へ改訂。12章の改訂履歴も更新。

## 根拠

- 実機の不具合原因は「windows-curses が全角グリフでカーソルを1桁しか進めず、ラン内で
  後続文字が重なる」ことにあり、`addstr` に長い文字列を渡す限り再発しやすい。1文字ずつ
  確定桁へ描く案 A は PDCurses のカーソル前進挙動に依存しないため確実性が高い。
- 案 B（locale 設定のみ）は変更が小さいが、上記の根本原因を解消しないため却下。
- 案 C（装飾箇所のみ日本語）はユーザー要望（CLI表示は日本語に）を満たさないため却下。
- 案 D（curses をやめ自前 ANSI 描画）は影響範囲が過大で、今回の要望に対し不釣り合いなため却下。
- ASCII 切替オプションは、コード分岐と表示仕様が二重化してメンテコストが増える割に、
  実用上は CJK 等幅フォントの端末で遊ぶ前提で足りると判断し不採用。
