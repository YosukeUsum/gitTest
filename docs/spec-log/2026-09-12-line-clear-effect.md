# SPEC壁打ちログ: ライン消去時のエフェクト追加

- 起票日: 2026-09-12
- 関連SPEC項目: FR-16(新規)、NFR-11(新規)、AC-13(新規)、12章
- ステータス: 決定済み
- 参加: ユーザー / Claude

## 背景・きっかけ

ユーザーから「消えた時のエフェクトが欲しいから追加して」との依頼。現状の実装
(`Board.clear_lines()` / `Game._lock_and_advance()`)は、行が完成すると同一フレーム内で
即座に盤面から消去され、上のブロックが詰められる。視覚的な変化が一切なく、
「消えた」ことが一瞬すぎてわかりにくい。

## 論点

- 「エフェクト」をどう実現するか(色の点滅、行のスライドアニメーション、テキスト表示等)。
- エフェクトの表示中、ゲーム進行(重力による落下・新規ミノ出現・プレイヤー操作)を
  どう扱うか。
- エフェクトの時間管理を、既存のアーキテクチャ方針(NFR-3: ロジック層はcursesに非依存、
  pytestで単体テスト可能)にどう適合させるか。
- 色非対応端末(NFR-9/NFR-10のフォールバック方針)でも同様にエフェクトを表現できるか。
- 標準8色を使い切っている現状(FR-14/FR-15)で、新しいエフェクト用の色を追加できるか。

## 検討した選択肢

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| A. 点滅(反転表示)+ 消去を一定時間遅延 | 行が完成したら即座に消さず、`Game` に消去対象行と残り時間を保持させる。UI側は残り時間から点滅の位相を計算し、`curses.A_REVERSE`(反転表示)で対象行を点滅させたのち、時間経過後に実際に盤面から消去する | `curses.A_REVERSE` は色を使わない標準属性のため、色対応・非対応端末のどちらでも同じ仕組みで動作する(新しい色を用意する必要がない)。時間管理ロジック(残り時間のカウントダウン)は既存のゲームループ(`FixedTimestepLoop`)と同様にcursesに非依存な形で実装でき、pytestで単体テスト可能。実装・変更範囲が小さい | 「消える」演出としてはシンプル(点滅のみ)で、スライドや파티클のような派手さはない |
| B. 行のスライド/詰めアニメーション | 消去対象行を消したあと、上のブロックが1行ずつ実際に落ちてくる様子を複数フレームに分けて描画する | 見た目の演出として最もリッチ | 中間状態(何行分詰まったか)を保持・補間する必要があり実装・テストコストが大きい。既存の「盤面はimmutableな2次元配列で即座に確定する」という設計(`Board.grid`)を複数フレームにまたがる可変状態に変える必要があり、変更範囲が大きい |
| C. テキストメッセージ表示のみ(例:「Line Clear!」) | ブロックの見た目は変えず、サイドバー等に一時的なメッセージを表示する | 実装が最も簡単 | ユーザーの要望(「消えた時の」エフェクト)は、ブロックそのものの視覚的な変化を期待していると考えられ、メッセージ表示だけでは要望に直接応えられない |

## やり取りの要旨

- Claude: 標準8色をすでにミノ7種+UIアクセント4種で使い切っている(FR-14/FR-15)ため、
  エフェクト用に新しい色相を追加することは難しい。`curses.A_REVERSE`(反転表示)は
  色を使わない標準機能で、色対応・非対応端末のどちらでも動作するため、これを使った
  点滅エフェクトが最も既存方針(NFR-1・NFR-9・NFR-10)と整合すると判断し、案Aを採用する
  方針とする。
- エフェクト表示中(点滅中)は、重力による落下や新規ミノの出現、プレイヤーの移動・回転・
  ドロップ操作を一時停止し、実際のテトリスのゲームフィールに近い「間」を作る。

## 決定事項

- 案Aを採用する。
  1. `Board` に、行を消去せず完成行のインデックスのみを返す `find_full_rows()` と、
     指定した行を消去して上に空行を詰める `remove_rows(rows)` を追加する。既存の
     `clear_lines()` はこの2つを組み合わせて実装し直し、外部から見た挙動(即座に消去し
     消去行数を返す)は変えない(`tests/test_board.py` の既存テストと後方互換)。
  2. `Game` に `clearing_rows`(消去対象の行番号のリスト)と `clear_effect_remaining`
     (エフェクトの残り時間・秒)を追加する。ミノがロックされ行が完成した際、スコア・
     消去ライン数・レベルは即座に更新するが、盤面からの実際の消去と次のミノの出現は
     `clear_effect_remaining` が0になるまで遅延させる。
  3. `Game.update(elapsed_seconds)` を新設し、UI側から毎フレーム(重力の固定タイム
     ステップとは独立に)呼び出す。残り時間を減算し、0以下になったら
     `board.remove_rows()` を呼んで実際に消去し、次のミノを出現させる。
  4. `Game.clear_effect_blink_on` プロパティで、経過時間と点滅間隔から
     「点滅の表示フェーズ」かどうかを返す(cursesに非依存、pytestで単体テスト可能)。
  5. エフェクト表示中(`clearing_rows` が空でない間)は、`tick()`(重力)・移動・回転・
     ソフト/ハードドロップの操作を無効化する(`game_over`・`paused` と同様の「ビジー」
     状態として扱う)。
  6. `ui_curses.py` の `_draw_board()` で、消去対象行かつ点滅の表示フェーズのときのみ
     `curses.A_REVERSE` を追加で適用し、そのセルを反転表示にする。色対応・非対応端末の
     どちらでも同じロジックで動作する(NFR-11)。
  7. エフェクトの表示時間・点滅間隔は定数として定義し、具体的な秒数はコード上に明記する。

## 根拠

- 案Aは、色を追加せず標準の反転表示属性のみで実現できるため、既存の色運用(FR-14/FR-15で
  標準8色を使い切っている状況)と衝突しない。時間管理ロジックをcursesに非依存な形で
  `Game` に持たせることで、既存のアーキテクチャ方針(NFR-3、および固定タイムステップの
  前例であるNFR-8)と一貫性が保て、pytestでの単体テストも可能になる。
- 案B(スライドアニメーション)は見た目はよいが、盤面の状態管理を複数フレームにまたがる
  形に変更する必要があり、変更・テストコストが要望の大きさに見合わない。
- 案C(メッセージのみ)は「消えた時の」エフェクトというユーザーの要望の核心(ブロックの
  視覚的な変化)に応えられないため不採用。
