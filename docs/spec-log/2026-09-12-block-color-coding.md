# SPEC壁打ちログ: ブロックの種類ごとの色分け表示

- 起票日: 2026-09-12
- 関連SPEC項目: FR-14(新規)、NFR-9(新規)、12章
- ステータス: 決定済み
- 参加: ユーザー / Claude

## 背景・きっかけ

ユーザーから「ゲーム内でブロックが白と黒しかなく、色がなくてわかりにくいから色分けして
ほしい」との依頼。現状の `ui_curses.py` は `stdscr.addstr` に色属性を一切指定しておらず、
すべてのブロックが端末のデフォルト色(白黒)で描画されている。

## 論点

- テトリミノの種類(I/O/T/S/Z/J/L)ごとにどの色を割り当てるか。
- `curses` の標準8色(BLACK/RED/GREEN/YELLOW/BLUE/MAGENTA/CYAN/WHITE)には「オレンジ」が
  無いため、慣習的にオレンジが割り当てられる L ミノをどう扱うか。
- 端末が色表示に対応していない場合(`curses.has_colors()` が `False`)のフォールバック。
  NFR-1(標準ライブラリのみで動作)を踏まえ、色非対応環境でもクラッシュせず遊べることが
  必須。
- `board.py` の盤面グリッドが既に各セルへミノ種別ごとの色ID(`tetromino.KIND_TO_COLOR`、
  1〜7の整数)を保持している設計をどう活かすか。
- 描画方式の変更範囲(盤面のブロックのみか、サイドバーのラベル等も含めるか)。

## 検討した選択肢

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| A. curses色ペアでブロックのみ色分け | `curses.start_color()`/`init_pair()` で盤面のセル(落下中ピース・固定ブロック)のみ色分けする。既存の `board.grid` の色ID(1〜7)をそのまま `curses.color_pair()` の番号に使う。`has_colors()` が `False` の場合は従来通りモノクロ描画にフォールバック | 既存のデータモデル(色ID)をそのまま活用でき変更範囲が小さい。ユーザーの要望(ブロックが分かりにくい)に直接応える。フォールバックで非対応端末でも動作 | 標準8色にオレンジが無くLミノの色に妥協が必要 |
| B. Aに加えサイドバー・ネクスト表示も色付け | 上記に加え、ネクストミノのラベルや盤面外の表示も対応する色で着色する | 視認性がさらに上がる | 今回の要望(ブロックの色分け)の範囲を超える。変更・検証コストが増える |
| C. 256色/RGBによる正確なオレンジ表現 | `curses` の拡張(`curses.COLOR_PAIRS` 拡張や `curses.init_color`)で256色端末向けに正確なオレンジを定義し、非対応端末には別途フォールバック | 見た目が本家テトリスに近づく | 対応端末が限られる(Windowsコンソール/一部ターミナルは非対応)。実装・分岐が複雑化し、本プロジェクトの「標準ライブラリのみ・シンプルさ」の方針(NFR-1)に反する |

## やり取りの要旨

- Claude: 標準8色にはオレンジが無いため、Lミノの代替色(白 or 別色)が必要になる旨、
  および端末が色非対応の場合のフォールバックが必要な旨を踏まえ、案Aで進めることを想定。
  変更範囲は「盤面のブロック(落下中ピース・固定ブロック)のみ」とし、サイドバー等は
  対象外とする(要望が「ブロックが分かりにくい」に限定されているため)。

## 決定事項

- 案Aを採用。テトリミノの種類ごとに以下の `curses` 標準色を割り当てる。

  | ミノ | 割り当て色 |
  |---|---|
  | I | シアン |
  | O | 黄 |
  | T | マゼンタ |
  | S | 緑 |
  | Z | 赤 |
  | J | 青 |
  | L | 白(標準8色にオレンジが無いための代替) |

- `board.grid` に既に保持されているミノ種別ごとの色ID(1〜7、`tetromino.KIND_TO_COLOR`)を
  そのまま `curses.color_pair()` の番号として使う(データモデルの変更なし)。
- `curses.has_colors()` が `False` の端末では、色初期化をスキップし従来通りモノクロで
  描画する(NFR-1のクラッシュしない要件を維持)。
- 変更範囲は盤面のブロック(落下中ピース・固定ブロック)のみとし、サイドバーのラベルや
  罫線は現状の表示を維持する(案Bは見送り)。
- 色IDと `curses` 色定数の対応表はコード上でテスト可能な形(単純な辞書)にし、
  `tetromino.KIND_TO_COLOR` の全キー(7種)を漏れなくカバーしていることを
  単体テストで検証する。

## 根拠

- 案Aはユーザーの要望(ブロックが分かりにくい)に直接応えつつ、既存の色IDデータモデルを
  再利用できるため変更が小さく安全。案Bは要望の範囲を超えるため今回は見送り(将来別テーマ
  として壁打ち可能)。案Cは対応端末が限られるうえ「標準ライブラリのみ・シンプルに保つ」
  という既存方針(NFR-1)に反するため不採用。
- Lミノの代替色は、標準8色の中で他の6色(I/O/T/S/Z/J)と重複しない残り1色である「白」を
  採用した。
